# GymSnap — сгенерированные иллюстрации упражнений

## Где что лежит

| Что | Где |
|---|---|
| Сам файл картинки | Vercel Blob, `exercises/<exerciseId>/v<N>.webp` |
| Ссылка и метаданные | таблица `exercise_images` |
| Текст промпта, по которому нарисовано | колонка `exercise_images.prompt` |
| Из чего собирался промпт | таблица `exercise_image_specs` |
| Внешний вид (стиль, ракурсы, пул фигур) | `lib/image-prompt.ts` |
| Исходные фото free-exercise-db | `exercises.images` — **не трогаются никогда** |

Ключевое: `exercises.images` остаётся нетронутым. `npm run seed` можно гонять сколько
угодно, он ничего не затрёт. Приложение читает картинки через `lib/exercise-images.ts`,
который сначала смотрит в `exercise_images` со статусом `active`, и только если её нет,
отдаёт фото с GitHub.

Из этого следует: **откат не требует восстановления данных.** Снимаешь активную строку —
упражнение само возвращается к исходному фото.

## Статусы

- `pending` — свежесгенерированная, **ждёт приёмки**. В приложении не показывается.
  Это дефолт для всего, что рисует `generate`: ничего не уезжает к пользователю,
  пока человек на это не посмотрел. Несколько pending на упражнение допустимы —
  частичный уникальный индекс покрывает только `active`.
- `active` — показывается в приложении. На упражнение ровно одна, гарантируется
  частичным уникальным индексом.
- `archived` — предыдущая версия. Файл в Blob цел, можно откатиться.
- `rejected` — брак. В откат не предлагается, файл можно удалить через `prune`.

## Команды

```bash
npm run images status                          # что уже сделано
npm run images -- specs --limit 50             # спеки через Claude
npm run images -- generate --limit 20          # картинки через OpenAI, статус pending
npm run images -- generate --quality low       # тот же прогон дешевле, для сравнения
npm run images -- generate --only barbell-squat --dry   # показать промпт, не генерить
npm run images -- approve barbell-squat        # pending -> active
```

Флаги идут после `--`, иначе npm заберёт их себе.

Обе генерирующие команды берут только то, чего ещё нет: `specs` — упражнения без спеки,
`generate` — упражнения без картинки в статусе `active` или `pending` (иначе повторный
запуск перерисовывал бы, и переоплачивал, всё, что просто лежит в очереди на приёмку). Прерывать можно в любой момент,
повторный запуск продолжит с того же места. БД и есть манифест, отдельного файла нет.

## Локальная страница `/admin/images`

Всё то же самое, но глазами. **Только локально** — страница и её API-роуты отдают 404
при `NODE_ENV === "production"`, ссылки из навигации на неё нет. Защиты у неё никакой,
и каждый клик стоит денег.

- **Очередь** (`/admin/images`) — таблица с фильтрами (нет спеки / нет картинки /
  ждёт приёмки / отклонённые / готовые, плюс снаряд, категория и поиск), выбор
  чекбоксами и последовательный прогон с живым прогрессом. «Прервать» отменяет
  незапущенные; уже отправленный запрос дорабатывает — обрывать его значило бы
  заплатить за картинку и выбросить её.
  Спеки тоже делаются отсюда — кнопка «Сделать спеки» прогоняет всё, что показано
  в списке без спеки. Это шаг на Claude: центы, а не доллары, как картинка,
  поэтому подтверждения он не спрашивает.
- **Упражнение** (`/admin/images/<id>`) — собранный промпт в редактируемом поле, поля
  спеки по отдельности, вычисленный размер холста, выбор `quality`, результат сразу
  в двух размерах (во всю ширину и 180px — реальный размер превью в карточке дня;
  решение принимается по маленькому), Approve / Reject / Regenerate и история версий
  с промптом каждой попытки. Сохранение спеки ставит `edited_by_hand = true`.
- **Приёмка потоком** (`/admin/images/review`) — по одной pending на экран,
  `A` approve, `R` reject, `G` перегенерить, стрелки листать.

Сверху — оценка расходов по числу строк и константе цены за тир из
`lib/image-generation.ts`. Это **оценка, а не биллинг**: она не видит оплаченных
неудачных вызовов и изменений прайса. Точные цифры только в консоли OpenAI.

## Как заменить картинку

**Перегенерить.** `generate --only <id>` создаёт новую версию в статусе `pending`.
Активная картинка при этом не трогается — она уступит место только после `approve`.
Если принятый результат оказался хуже — `rollback <id>`.

**Поправить, что рисуется.** Правишь строку в `exercise_image_specs` (описание панелей,
ракурс, число фаз, внешность фигуры), ставишь `edited_by_hand = true`, чтобы
пересчёт спек её не перезаписал, и запускаешь `generate --only <id>`.

**Поменять стиль всей библиотеки.** Правишь блоки в `lib/image-prompt.ts` и **обязательно**
поднимаешь `TEMPLATE_VERSION`. Иначе в библиотеке окажутся картинки, нарисованные по
разным шаблонам, и заметить это будет нечем.

**Подложить свою.** Вставляешь строку в `exercise_images` с `source: "manual"` и
статусом `active`, предварительно переведя текущую активную в `archived`.

## Как восстановить

```bash
npx tsx scripts/images.ts rollback <id>              # предыдущая версия
npx tsx scripts/images.ts rollback <id> --version 2  # конкретная
npx tsx scripts/images.ts reject <id> --note "гриф на пояснице"
npx tsx scripts/images.ts disable <id>               # вернуть на free-exercise-db
```

`reject` и `disable` не удаляют ничего — упражнение просто перестаёт находить активную
картинку и падает на фолбэк. `prune` удаляет из Blob файлы забракованных версий,
строки в БД остаются как история того, что было забраковано и почему.

## Что подключить в приложении

1. Заменить старый `exerciseImageUrl()` на версию из `lib/exercise-images.ts` — она
   пропускает абсолютные URL и клеит префикс GitHub только относительным путям.
2. На странице плана использовать `resolveImagesBatch(ids)` — один запрос вместо N.
3. `ImageLightbox` рассчитан на два кадра start/end; у сгенерированных картинка одна,
   фазы внутри неё. Листалку убрать.
4. Превью в карточке дня и в `@media print` расширить: одна широкая картинка вместо двух,
   место в ряду освобождается, при 90px панели не читаются.

## Порядок первого прогона

1. Миграция: добавить таблицы, `npm run db:generate && npm run db:migrate`.
2. `OPENAI_API_KEY` в `.env.local`. В Vercel **не добавлять** — приложение к OpenAI не ходит.
3. `specs --limit 10`, глазами проверить пару строк в `exercise_image_specs`.
4. `generate --limit 3`, посмотреть результат.
5. Дальше пакетами, начиная с custom-лестниц (у них нет фото вообще) и упражнений,
   реально попадающих в планы. Длинный хвост библиотеки может остаться на free-exercise-db.

## Известные ограничения

- Модель стабильно рисует один блин на сторону вместо двух, сколько ни проси. Если
  критично — ловить выборочной проверкой.
- Логотипы на кроссовках иногда протаскиваются вопреки запрету.
- Высота фигуры между панелями слегка гуляет. Признано некритичным.
- `gpt-image-2` пришпилен намеренно. Алиас `chatgpt-image-latest` подвижный и уедет
  посреди прогона, разделив библиотеку на два стиля.
